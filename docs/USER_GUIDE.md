# custom-harness 사용자 가이드

- 문서 목적: 폐쇄망 사용자가 **번들만 가지고** 설치부터 일상 사용까지 갈 수 있게 한다.
- 대상 독자: 사내 개발자 (배포·반입 등 운영 담당자 절차는 [운영 가이드](./OPERATIONS.md)를 따른다)
- 상태: active (2026-09-02 최초 작성 — WBS 3.6.1)
- 최종 수정일: 2026-09-02
- 배포 형태: 저장소 원본이 SSOT 이며, 번들 루트에 `USER_GUIDE.md`·`OPERATIONS.md`로 동봉된다 (폐쇄망에서 저장소 접근 없이 읽기 위함)

---

## 1. 이 도구가 하는 일

custom-harness 는 **여러 코딩 에이전트 하네스를 하나의 데스크톱 앱에서 쓰게** 해 준다.
에이전트 루프(모델 호출·툴 실행 판단)는 하네스가 소유하고, 이 도구는 하네스의 **실행·상태·UI**
를 소유한다.

- 동봉 하네스: **pi**, **omp**(oh my pi), **grok**(grok build — _Windows 번들 제외_)
- 모든 LLM 트래픽은 사내 게이트웨이만 경유한다. 하네스가 인터넷으로 나가는 경로는 설치 시
  차단 설정이 주입된다.
- 설치·실행 중 외부 다운로드가 **0** 이다. 번들 하나가 전부다.

## 2. 설치

### 2.1 스크립트 설치 (권장)

1. 반입한 아카이브의 sha256 을 동봉된 `.sha256` 파일과 대조하고 해제한다.
2. 해제한 디렉토리에서:
   - macOS / Linux: `./install.sh`
   - Windows: `powershell -ExecutionPolicy Bypass -File .\install.ps1`
3. 완료 메시지의 실행 경로를 확인한다.

설치기는 **체크섬 검증 → 버전 디렉토리 배치 → 오프라인 프리셋 주입 → `current` 전환(원자) →
실행 진입점 생성** 순으로 진행한다. 관리자 권한은 필요 없다(사용자 홈에 설치).

> 중간에 실패하면 **기존 설치는 그대로 남는다.** `current` 전환이 마지막 단계이고, 그 전에
> 죽으면 이전 버전이 계속 활성이다.

### 2.2 설치 위치

```
~/.custom-harness/
├── bin/            실행 진입점 (custom-harness, custom-harness-rollback)
├── current   →     versions/<설치본> 심링크 (Windows: junction)
├── versions/       설치된 버전들 (롤백 대상이라 보존된다)
├── data/           세션 이력·설정·크리덴셜 — 버전 밖이라 업데이트·롤백에 영향 없음
└── logs/           데몬·세션 로그 (첫 기동 시 생성)
```

기억할 것은 하나다: **`data/` 는 버전 디렉토리 밖에 있다.** 업데이트해도 롤백해도 세션 이력과
설정은 그대로다.

### 2.3 실행

- GUI: `~/.custom-harness/bin/custom-harness`
- CLI: `~/.custom-harness/bin/custom-harness daemon status`

`bin` 을 `PATH` 에 넣어 두면 `custom-harness` 로 바로 쓸 수 있다.

### 2.4 서명되지 않은 앱 경고

사내 인증서 적용 전에는 macOS Gatekeeper / Windows SmartScreen 경고가 뜰 수 있다.
반입 절차로 검증된 아카이브라면 조직 안내에 따라 허용한다.

## 3. 최초 실행 (온보딩)

앱을 처음 열면 3단계 마법사가 뜬다.

| 단계         | 입력                                                | 비고                                                                            |
| ------------ | --------------------------------------------------- | ------------------------------------------------------------------------------- |
| ① 게이트웨이 | 주소(`http://gateway.internal/v1` 형태) + 기본 모델 | 번들에 프리셋이 있으면 확인만 하고 지나간다                                     |
| ② API 키     | 게이트웨이 API 키                                   | 저장 즉시 **연결 확인**까지 한다 — 실패하면 원인(네트워크/401/형식)을 알려 준다 |
| ③ 확인       | 사용 가능한 하네스 목록                             | 여기까지 오면 준비 완료                                                         |

키는 OS 보안 저장소(macOS 키체인 등)에 저장된다. 보안 저장소를 쓸 수 없는 환경이면 파일 권한
0600 폴백으로 저장하고, 설정 화면에 그 사실을 경고로 표시한다 — 표시가 떠 있으면 그 PC 의 키는
파일 권한만으로 보호되는 상태다.

## 4. 기본 사용

### 4.1 워크스페이스부터 만든다

세션은 **워크스페이스에 속한다**. 사이드바의 **+ 워크스페이스** 로 작업할 디렉토리를 연다.

격리 방식 두 가지:

| 방식        | 동작                                       | 언제                                                                    |
| ----------- | ------------------------------------------ | ----------------------------------------------------------------------- |
| `directory` | 그 디렉토리에서 그대로 작업                | 평소. 이미 체크아웃해 둔 저장소                                         |
| `worktree`  | git worktree 를 따로 만들어 그 안에서 작업 | 여러 작업을 **같은 저장소에서 동시에** 굴릴 때. 브랜치가 서로 안 밟힌다 |

`worktree` 는 기존 브랜치를 체크아웃하거나(`--branch`), 새 브랜치를 분기할 수 있다
(`--branch` + `--base-branch`).

### 4.2 세션 시작

사이드바의 **+ 새 세션**(`Mod+N`) → 하네스와 모델을 고르고 시작한다. 프롬프트를 입력하면 턴이 돈다.

- 응답·사고 과정·툴 실행이 타임라인에 순서대로 쌓인다.
- 실행 중 중단은 `Mod+.`
- 탭을 닫아도(`Mod+W`) **세션은 종료되지 않는다.** 세션 종료는 사이드바의 세션 항목에서 한다
  (종료해도 이력은 남고 재개할 수 있다).

### 4.3 승인

하네스가 파일을 고치거나 명령을 실행하려 하면 **승인 카드**가 뜬다. 원본 상세를 펼쳐 무엇을
하려는지 확인하고 허용/거부를 고른다.

**자동 승인**은 세션 단위 opt-in 이고 **앱을 재시작하면 풀린다**. 켜 두면 그 세션의 하네스 출처
승인이 자동 통과한다. 역방향 툴 요청은 항상 직접 승인해야 한다 — 되돌리기 어려운 작업을 시키는
세션에서는 켜지 않는 편이 낫다.

### 4.4 사이드바 버킷 — "지금 나를 기다리는 것"

세션은 상태별 버킷으로 묶인다: **승인 대기 · 확인 필요 · 실행 중 · 유휴 · 에러 · 완료·보관**.

여러 세션을 동시에 돌릴 때 화면을 훑을 필요가 없도록, 사용자의 개입이 필요한 세션이 위쪽
버킷으로 올라온다. 네이티브 알림(설정에서 on/off)도 승인 대기·턴 완료/실패에서 뜬다.

### 4.5 작업 캔버스 — 터미널·파일·diff

사이드바 위쪽 버튼 줄(**+ 터미널 · 파일 · 변경사항**)로 열어 세션 탭 옆에 함께 둔다.

- **터미널**: 워크스페이스 경로에서 열리는 실제 셸. 앱을 닫으면 데몬과 함께 종료된다.
- **파일 탐색기 / 뷰어**: 워크스페이스 안의 파일을 연다.
- **변경사항(diff)**: 작업 트리의 변경을 본다. 하네스가 고치는 동안 갱신된다.

분할 보기는 탭 바에서 좌우/상하로 나눌 수 있다. 배치는 앱을 다시 열어도 복원된다.

### 4.6 커맨드 팔레트 (`Mod+K`)

세션·워크스페이스·파일·명령을 한 입력창에서 찾는다. 대화 **내용**도 검색된다 — 지난주에 어떤
세션에서 그 오류를 봤는지 기억나지 않을 때 문구로 찾아 그 지점으로 바로 간다.

### 4.7 서브에이전트 위임 (선택)

역방향 툴을 켜면 하네스가 **다른 세션을 만들어 일을 나눠 줄 수** 있다(`session_new`,
`session_say`, `session_wait`, `term_send` 등).

**기본은 꺼져 있다.** 켜는 것이 위험한 쪽이라 그렇다 — 켜면 하네스가 다른 세션의 타임라인을 읽고,
프롬프트를 보내고, 터미널에 입력할 수 있다. 설정에서 명시적으로 켠 뒤 앱을 재시작해야 적용된다
(`tools.reverseExposure`).

안전장치 둘이 함께 걸린다: **깊이 상한**(기본 1 — 자식은 손자를 못 만든다)과 **팬아웃 상한**
(기본 1 — 동시에 살아 있는 자식 수). 상한이 없으면 프롬프트 하나가 세션을 지수로 늘리고 그
각각이 토큰을 쓴다. 자식 세션은 부모 화면 위쪽 **트랙**에 상태와 누적 사용량으로 표시된다.

## 5. 설정

사이드바 위쪽 버튼 줄의 **설정** 에서:

- **게이트웨이**: 주소·기본 모델·동시 세션 상한
- **API 키**: 등록·변경, 보안 저장소 사용 여부 표시
- **하네스 상태**: 하네스별 가용성·버전·manifest 검증 결과·경고
- **알림·승인 정책**: 네이티브 알림 on/off, 자동 승인이 켜진 세션 수
- **앱 정보 · 오픈소스 고지**: 버전·번들 신원과 동봉 오픈소스 고지 열람

세밀한 값은 `~/.custom-harness/data/settings.json` 에서 직접 고칠 수 있다(앱이 켜져 있어도 즉시
반영된다 — `tools.reverseExposure` 만 재시작 필요).

| 키                       | 기본값               | 뜻                                                         |
| ------------------------ | -------------------- | ---------------------------------------------------------- |
| `maxSessions`            | 8                    | 동시 세션 상한                                             |
| `autoApprove`            | false                | 전 세션 자동 승인 (권장하지 않음)                          |
| `workspace.setupAutoRun` | false                | 프로젝트 `harness.json` 의 setup 자동 실행                 |
| `harness.homeIsolation`  | true                 | 하네스에 빈 홈을 주어 외부 설정 유입 차단 — **끄지 말 것** |
| `harness.homeLinks`      | `.gitconfig`, `.ssh` | 격리 홈에 반입할 실제 홈 항목 allowlist                    |
| `tools.reverseExposure`  | false                | 역방향 툴(위임) 노출 — 재시작 필요                         |
| `tools.maxSessionDepth`  | 1                    | 위임 깊이 상한                                             |
| `tools.maxFanout`        | 1                    | 동시 자식 세션 수 상한                                     |
| `session.titleMode`      | `heuristic`          | 세션 제목 생성 — `off` / `heuristic` / `llm`               |

`session.titleMode` 의 기본이 `heuristic`(비 LLM)인 이유는 제목 한 줄에 모델 호출을 붙이면 세션을
만들 때마다 토큰이 나가기 때문이다. `llm` 은 켜는 쪽이 선택이다.

## 6. CLI

GUI 없이 스크립트로 쓸 수 있다. **모든 명령에 `--json`** 을 붙이면 기계 판독 출력이 나온다.

```sh
custom-harness daemon start|stop|status      # 데몬 수명주기
custom-harness doctor                        # 설치 자가 진단
custom-harness logs [이름] [--lines N]        # 로그 목록 / 마지막 N줄
custom-harness version

custom-harness session list [--workspace ID] [--all]
custom-harness session new --harness <pi|omp|grok> [--cwd DIR] [--workspace ID] [--model M]
custom-harness session prompt <세션> <텍스트...> [--wait]
custom-harness session watch <세션> [--from-seq N]
custom-harness session interrupt|close <세션>
custom-harness session approve <세션> [--request ID] [--option ID] [--reject]

custom-harness workspace list [--project ID] [--all]
custom-harness workspace new (--project ID | --root DIR) [--isolation directory|worktree]
custom-harness workspace archive <워크스페이스> [--remove-checkout] [--force]
```

스트리밍은 **stdout 에 답만**, 툴 실행·승인·진단은 stderr 로 나간다. 그래서 이렇게 쓸 수 있다:

```sh
custom-harness session prompt s-1 "테스트 고쳐줘" --wait > answer.txt
```

`--json` 실패 응답은 stderr 로 나간다 — `cmd --json > out.json` 이 성공했을 때만 내용을 갖게 하기
위함이다.

## 7. 업데이트와 되돌리기

### 7.1 업데이트

새 번들을 반입해 **설치를 다시 하면** 그것이 업데이트다. 설치기가 알아서 판단한다.

- 실행 중인 데몬이 있으면 **멈추고 안내**한다. 동의하면 진행(비대화 환경은 `--force`).
- 이전 버전은 **지우지 않고 보존**한다(기본 3개, 설정 가능) — 롤백 대상이기 때문이다.
- `current` 전환은 마지막에 원자적으로 일어난다.

### 7.2 되돌리기

```sh
custom-harness-rollback --list      # 설치된 버전 목록
custom-harness-rollback             # 직전 버전으로 (설치 시각 기준)
custom-harness-rollback <버전>       # 특정 버전으로
```

이 명령은 **`current` 를 거치지 않고 동작한다.** 롤백은 current 가 깨졌을 때 쓰는 것이라, 평소
실행 경로를 타는 도구로는 정작 필요할 때 못 쓴다. 세션 데이터는 버전 밖이라 롤백해도 그대로다.

### 7.3 제거

```sh
./uninstall.sh                      # 프로그램만 제거 — 데이터 보존 (기본)
./uninstall.sh --purge              # 데이터까지 삭제 (대화식 확인, 비대화는 --yes 병행)
```

Windows 는 `uninstall.ps1` / `-Purge` / `-Yes`.

## 8. 문제가 생기면

### 8.1 먼저 `doctor`

```sh
custom-harness doctor
```

데몬 · manifest 체크섬 · 하네스 실행 파일과 버전 · 게이트웨이 연결 · 오프라인 프리셋 ·
트래픽 경계를 한 번에 본다. 대부분의 문제는 여기서 어느 칸이 깨졌는지로 좁혀진다.

### 8.2 로그

```sh
custom-harness logs                 # 목록
custom-harness logs daemon --lines 200
```

경로는 `~/.custom-harness/logs/`.

### 8.3 자주 묻는 것

**Q. 인터넷이 안 되는데 설치·실행이 되나?**
그렇게 만든 도구다. 설치·실행 중 외부 접속이 0 이고, 자동 검증 스모크가 그것을 매번 확인한다.
게이트웨이만 닿으면 된다.

**Q. 내 API 키는 어디에 저장되나?**
OS 보안 저장소. 쓸 수 없는 환경이면 `~/.custom-harness/data/` 에 권한 0600 파일로 저장하고 설정
화면에 경고를 띄운다.

**Q. 하네스가 내 개인 설정(`~/.claude` 등)을 읽나?**
읽지 않는다. 하네스마다 **빈 홈**을 만들어 주고 `HOME`·`USERPROFILE`·XDG 변수를 그쪽으로
덮는다. 실제 홈에서 반입되는 것은 allowlist 항목(`.gitconfig`, `.ssh`)뿐이다. 이 격리를 끄면
하네스가 외부 MCP 서버 설정을 읽어 게이트웨이 밖으로 나갈 수 있다 — 그래서 기본이 on 이다.

**Q. 앱을 닫으면 세션이 죽나?**
그렇다. 창을 닫으면 앱과 앱 소유 데몬이 함께 종료되며, 실행 중인 세션·터미널도 끝난다. CLI로
별도 기동한 데몬은 앱이 종료하지 않는다.

**Q. Windows 에서 grok 이 안 보인다.**
Windows 번들에는 grok 이 동봉되지 않는다(upstream 이 Windows 빌드를 "best-effort·미테스트"로
두고 배포 asset 도 없다). Windows 는 omp + pi 로 쓴다.

**Q. 세션을 여러 개 돌리면 토큰이 걱정된다.**
같은 작업을 여러 하네스에 동시 실행하는 기능은 **일부러 넣지 않았다.** 위임도 깊이·팬아웃
상한이 기본 1 이다. 세션별·자손 합산 사용량은 UI 에서 볼 수 있다.

**Q. 동봉된 오픈소스 라이선스는 어디서 보나?**
앱의 _설정 → 앱 정보 · 오픈소스 고지_. 번들 파일로는 `licenses/NOTICE.md` 와 `licenses/` 하위
원문.

**Q. 업데이트했더니 문제가 생겼다.**
`custom-harness-rollback` 으로 직전 버전으로 되돌린다. 세션 이력·설정은 영향받지 않는다.
