# clean-room · 고지 검수 기록 (NFR-4 / FR-4.5)

- 문서 목적: 릴리스 전 라이선스 준수 검수의 **방법·범위·한계**를 고정하고, 수행 결과를 기록한다.
- 상태: active (2026-09-02 최초 검수 — WBS 3.3.2)
- 최종 수정일: 2026-09-02
- 관련 문서: [NFR-4](../requirements/nfr.md), [FR-4.5](../requirements/fr4-packaging.md), [dev-standards §3](../design/dev-standards.md), [packaging](../design/packaging.md)
- 재현: `npm run audit:cleanroom` (구현: `scripts/cleanroom-audit.mjs`)

## 1. 왜 스크립트인가

NFR-4 의 검증 항목은 원래 "코드 리뷰 체크리스트 + 릴리스 전 NOTICE 검수", 즉 사람이 보는
절차였다. 그대로 두지 않은 이유는 두 갈래 모두 **조용히 깨지는 종류**이기 때문이다.

- 의존성 한 줄을 추가하면 고지에서 빠진다 — 추가한 사람은 고지를 생각하지 않는다.
- 파일 하나를 옮겨 붙이면 clean-room 이 깨진다 — 리뷰어가 원본을 모르면 못 잡는다.

릴리스 직전 한 번 눈으로 보는 것으로는 이 둘을 못 막는다. 그래서 검수를 명령으로 만들고,
그 명령이 무엇을 보는지(그리고 **무엇을 보지 않는지**)를 이 문서에 적는다.

## 2. 검사 항목

| #   | 검사            | 근거                      | 판정 기준                                                                                                                                                           |
| --- | --------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ①   | paseo 참조 경계 | NFR-4 ①, dev-standards §3 | 코드 트리(`packages/*/src`, `scripts/`, `bundle/`)에 `paseo` 언급 0. 분석 문서 2종 실재. 저장소에 paseo 경로 산출물 0                                               |
| ②   | copyleft 의존성 | NFR-4 ①                   | 워크스페이스 런타임 의존성의 `license` 에 AGPL/GPL/LGPL/SSPL/CC-BY-SA/EUPL 없음                                                                                     |
| ③   | 고지 완전성     | FR-4.5                    | **실제 동봉된 것**(manifest 하네스 + Electron + `app/node_modules`)이 전부 NOTICE.md 에 있고, 표가 가리키는 원문 파일이 실재하며 비어 있지 않음. PROVENANCE.md 존재 |
| ④   | 고지 정합성     | FR-4.5                    | manifest 버전 = notices.json 버전. NOTICE.md 표 행 수 = notices.json 항목 수. 고지된 라이선스에 copyleft 없음                                                       |

③ 의 고지 대상을 목록으로 적어 두지 않고 **번들에서 역산**하는 것이 요점이다. 목록을 손으로
관리하면 그 목록이 곧 두 번째 SSOT 가 되고, 빠진 항목은 목록에도 없으므로 영영 안 잡힌다.

### paseo 언급이 문서에 남아 있는 것은 위반이 아니다

clean-room 은 "참고하지 않는다"가 아니라 "**분석 문서를 매개로만** 참고한다"이다
(NFR-4 ①). 그래서 검사 ① 은 문서의 언급을 허용할 뿐 아니라 분석 문서의 **실재를 요구**한다 —
문서에 남은 언급이 설계 경로가 문서를 거쳤다는 증거다. 코드에서만 0 이면 된다.

유일한 코드 예외는 번들 NOTICE 에 찍는 고지 문구 자체
(`본 도구는 paseo(AGPL-3.0)의 코드를 포함하지 않는다`)이며 스크립트에 명시 허용돼 있다.

## 3. 이 검수가 보지 않는 것 (한계)

- **고지 버전 ↔ 실물 바이너리**: ④ 가 대조하는 것은 manifest 와 고지, 즉 *빌드가 적어 둔 두
  값*이다. 조달된 실물이 그 버전인지는 조달 단계(FR-4.7)의 몫이다. Grok 은 2026-09-02부터
  Darwin 로컬 바이너리의 `--version`과 `sources.json` 핀을 빌드 전에 대조하고, Linux 조달물은
  고정 SHA-256을 확인한다. 그래도 ④ 의 PASS 자체를 "고지가 실물과 같다"로 읽으면 안 된다.
- **소스 유사도**: 코드가 paseo 와 얼마나 닮았는지는 측정하지 않는다. NFR-4 도 유사도 검사
  도구 도입을 선택으로 뒀다. 여기서 보는 것은 "참조 경로가 문서를 거쳤는가"라는 절차 증거다.
- **전이 의존성의 라이선스**: ② 는 워크스페이스가 직접 선언한 런타임 의존성만 본다. 현재
  동봉되는 4종(zod·ws·yaml·smol-toml)은 전이 의존성이 없어 `app/node_modules` 최상위가 곧
  전부이며, ③ 이 그 트리를 역산하므로 실질 공백은 없다. 전이 의존성이 생기는 날에는 ② 의
  범위를 넓혀야 한다.
- **pi 패키지 내부의 의존성 고지**: pi 는 npm 패키지가 자기 `node_modules` 를 동봉한 형태
  그대로 재배포한다. 개별 고지는 패키지 안의 각 LICENSE 파일로 갈음하며(NOTICE.md 에 명시),
  이 스크립트는 그 트리를 훑지 않는다.

## 5. 앱 정보 화면 (FR-4.5 열람 요건)

고지는 동봉만으로 부족하고 **앱에서 열람 가능**해야 한다. 설정 → _앱 정보 · 오픈소스 고지_
(또는 커맨드 팔레트 `앱 정보`)에서:

- 버전·번들 신원(번들 버전·OS/arch·Electron·설치 경로)
- 동봉물 표(이름·버전·라이선스·원문 열기) — `licenses/notices.json` 을 그대로 그린다
- NOTICE.md · PROVENANCE.md 원문, 동봉 라이선스 파일 전체 목록

원문은 데몬이 `system.license.read` 로 **조각 단위**로 넘긴다. 20MB 인
`electron/LICENSES.chromium.html` 도 열람 대상이어야 해서 한 번에 싣지 않고 이어 읽는다 —
상한을 두고 잘라 버리면 그 원문은 앱에서 열람 불가가 되어 요건을 못 지킨다.

읽기 범위는 `licenses/` 안으로 봉쇄된다(`..`·절대경로·심링크 탈출 거절 — 워크스페이스 파일
뷰어와 같은 가드를 쓴다). 고지 열람 창구가 번들 임의 파일 읽기로 번지지 않게 하기 위함이다.
