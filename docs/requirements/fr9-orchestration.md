## FR-9.1 주의(attention) 상태 1급화 (M, M7) — **구현 완료 (2026-08-31, WBS 7.1.1~7.1.3)**

- 세션 레코드에 `requiresAttention` / `attentionReason`(`permission` | `error` | `finished`) / `attentionTimestamp` 를 **영속 필드**로 둔다. UI 파생값이 아니다.
- 데몬의 단일 정책 모듈(`packages/daemon/src/attention.ts`)이 이벤트에서 주의 상태를 계산하고, 변화가 있을 때만 `attention_changed` 이벤트를 발행한다.
- 사이드바 버킷·트레이 배지·OS 알림·자동 승인 정책이 모두 이 단일 상태를 소비한다(렌더러 로컬 계산에서 이관 완료).
- 클라이언트가 없는 동안 발생한 주의 상태는 재접속 시 그대로 조회된다 — `session.list` 응답에 항상 실리고, 데몬 재기동 후에도 보존된다.
- **확정된 정책** (구현이 정본): 사유 우선순위는 `permission` > `error` > `finished`. `session.attention.ack`(멱등)로 확인 처리하면 완료·에러 주의는 사라지지만 **승인 대기는 사라지지 않는다** — 화면을 본 것이 승인 응답을 대신하지 않는다. 실행 중(`running`·`initializing`)과 사용자가 스스로 멈춘 턴(`canceled`)은 주의 대상이 아니다. 같은 사유가 이어지는 동안 `attentionTimestamp` 는 최초 전이 시각을 보존한다("얼마나 기다렸나"가 정렬 기준이다). 새 프롬프트는 확인 처리와 같은 효과를 낸다.

## FR-9.2 역방향 툴 카탈로그 (S, M7)

- 데몬이 자신의 기능(세션 생성·프롬프트 전송·상태 조회·중단·워크스페이스 조회·터미널 조작)을 **툴 카탈로그 정본**으로 정의한다 — **2026-08-31 확정**: 툴 10종, [역방향 툴 카탈로그 설계](../design/reverse-tool-catalog.md) (WBS 7.2.2).
- 노출 경로는 **2가지**다 (2026-08-31 실측으로 확정 — [보고](../reference/harness-mcp-support.md)): ① MCP 를 지원하는 하네스(omp·grok)에는 데몬이 소유한 **MCP stdio 서버 1개**를 등록한다 ② MCP 를 지원하지 않는 하네스(pi)에는 같은 카탈로그를 **네이티브 확장**(`pi.registerTool`)으로 노출한다. 지원 여부는 capability 플래그로 협상한다.
- 노출은 기본 off, 세션 생성 시 명시적 opt-in. 자기 자신을 재귀 생성하는 경로에는 깊이·개수 상한을 둔다.
- **툴 이름은 짧게** — 하네스가 다시 접두사를 붙인다(omp `mcp__<server>_<tool>`, grok `<server>__<tool>`).
- 노출 이전에 성립해야 하는 조건 3건(실측에서 검출): ① 하네스가 사용자 실제 `$HOME` 의 외부 MCP 설정을 읽지 않도록 격리 ② grok 의 승인 모드가 MCP 툴 호출을 승인 요청 없이 거절하지 않도록 조정 ③ 프로젝트 스코프 `.mcp.json` 이 우리 서버명을 선점하지 못하도록 방어.

## FR-9.3 서브에이전트 (위임) (S, M7)

- 세션이 다른 세션을 자식으로 생성하고, 완료를 기다리거나 결과를 회수할 수 있다. 부모-자식 관계는 세션 레코드의 라벨로 표현한다.
- 자식 세션은 1급 세션이다 — 탭으로 열어 직접 대화할 수 있다.
- UI 는 부모 세션 화면에서 자식들의 상태를 한 줄 트랙으로 보여준다. 형제 세션(같은 워크스페이스의 독립 세션)은 탭/페인으로, 부모-자식은 트랙으로 구분한다.
- **토큰 제약 고려**: 팬아웃 개수 상한과 사용량 합산 표시를 필수로 한다.
- PURPOSE 의 제외 항목("크로스 하네스 중복 실행")과 구분한다 — 같은 작업의 중복 실행이 아니라 작업 분할·위임이다.

## FR-9.6 CLI 자동화 표면 확장 (S, M7) — **구현 완료 (2026-09-01, WBS 7.5.1~7.5.3)**

- 기존 데몬 제어(FR-5)에 더해 세션·워크스페이스 조작을 추가한다: 세션 생성·목록·프롬프트 전송·출력 스트리밍·중단·승인 응답, 워크스페이스 목록·생성·아카이브.
- 모든 명령에 기계 판독 출력(JSON) 옵션을 둔다 — 스크립트 조합이 자동화의 1급 경로다.
- FR-5.4 의 "에이전트 조작 범위 외" 제한은 이 항목의 승인으로 해제된다. → [FR-5.4](./fr5-cli.md) 문서에 반영 완료.

### 구현이 확정한 출력 규약

- **stdout 은 답, stderr 은 과정.** 스트리밍에서 어시스턴트 텍스트만 stdout 으로 가고 툴 실행·승인 요청·토큰은 stderr 로 간다. `session prompt … --wait > answer.txt` 가 기대대로 동작해야 한다.
- **`--json` 은 전역 플래그.** 명령마다 따로 해석하면 되는 명령과 안 되는 명령이 조용히 생긴다.
- **성공은 stdout 에 JSON 한 줄**(스트리밍만 이벤트 JSONL), **실패는 stderr 에 `{"error":{code,message}}`**. stdout 을 payload 전용으로 비워 둬야 리다이렉트한 파일이 성공했을 때만 내용을 갖는다. 종료 코드가 여전히 1차 신호이고 JSON 은 그 *이유*를 기계가 읽게 해 준다.
- **스트리밍 이벤트는 원시 `SessionEvent` 그대로** 흘린다. 프로토콜이 이미 계약이므로 CLI 가 자기 스키마를 하나 더 만들지 않는다.
- **파괴적·되돌릴 수 없는 조작은 명시 플래그가 확인을 갈음한다**(비대화형이므로): 활성 세션이 있는 워크스페이스 아카이브는 `--force`, 체크아웃 삭제는 `--remove-checkout`. 후자는 데몬이 관리 밖 경로를 거절해 사용자 자기 디렉토리를 CLI 한 줄로 지울 수 없다.
