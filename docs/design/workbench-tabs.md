- 최종 수정일: 2026-09-01
- 입력: [FR-8](../requirements/fr8-workbench.md), [워크스페이스 모델](./workspace-model.md), [프로토콜 설계](./protocol-design.md), [데몬 상세 설계](./daemon-design.md)

## 0. 설계 원칙 3개

1. **탭은 무엇을 보느냐이지 무엇을 소유하느냐가 아니다.** 탭을 닫는 것은 레이아웃 변경이고, 대상(세션·터미널)의 수명과 무관하다. 소유는 워크스페이스가 한다.
2. **같은 대상은 한 번만 열린다.** 탭 ID 를 타깃에서 결정적으로 유도해, 같은 파일·같은 세션이 두 탭에 흩어지지 않게 한다.
3. **터미널은 JSON 을 지나지 않는다.** 바이트 스트림을 문자열로 감싸면 인코딩 왕복과 이스케이프 비용이 매 키 입력마다 붙는다. 별도 채널로 보내고, 그 채널은 스키마 검증 밖에 둔다.

## 1. 탭 타깃 모델 (6.1.1)

### 1.1 타깃 유니온

```ts
type TabTarget =
  | { kind: 'new_tab' }                       // 빈 탭 — 무엇을 열지 고르는 자리
  | { kind: 'session'; sessionId: string }
  | { kind: 'terminal'; terminalId: string }
  | { kind: 'files' }                          // 워크스페이스 트리 탐색기
  | { kind: 'file'; path: string }             // 워크스페이스 상대 경로
  | { kind: 'diff'; scope: 'working' }         // 미커밋 변경
  | { kind: 'diff'; scope: 'commit'; sha: string };
```

- 현재 구현의 "탭 = 세션 ID 문자열"은 `{ kind: 'session' }` 으로 흡수된다. 마이그레이션은 §1.4.
- 새 타깃은 **유니온에 추가**하고 렌더러의 `switch` 가 컴파일 에러로 누락을 잡게 한다.

### 1.2 결정적 탭 ID

```
session:<sessionId> · terminal:<terminalId> · files · file:<path> · diff:working · diff:<sha>
```

- 같은 타깃을 다시 열면 **새 탭을 만들지 않고 기존 탭으로 포커스를 옮긴다**.
- `new_tab` 만 예외로 여러 개 존재할 수 있다(각각 임시 id).

### 1.3 레이아웃과 소유

- 레이아웃은 **워크스페이스 단위**로 보존한다: `layout[workspaceId] = { tabs, active, split }`. 워크스페이스를 바꾸면 그 워크스페이스에서 보던 배치가 그대로 돌아온다.
- 복원 시 **살아 있지 않은 타깃은 조용히 버린다**(닫힌 세션·사라진 터미널·삭제된 파일). 복원 실패가 화면 전체를 막지 않는다.
- 탭 닫기의 의미:

| 타깃 | 탭 닫기 | 대상 종료 |
|---|---|---|
| session | 레이아웃에서 제거. 세션은 워크스페이스에 남는다 | 사이드바의 명시적 종료 버튼 |
| terminal | 레이아웃에서 제거. pty 는 데몬이 계속 소유 | 터미널 목록의 명시적 종료 |
| file · diff · files | 레이아웃에서 제거 (부작용 없음) | — |

### 1.4 마이그레이션

- 저장된 레이아웃(`custom-harness.layout`)은 문자열 배열이다. 복원 시 문자열이면 `{ kind: 'session', sessionId }` 로 해석한다. 저장은 항상 새 형식으로 한다.
- 워크스페이스별 레이아웃 키가 없던 기존 배치는 **활성 워크스페이스의 배치로 1회 이관**한다.

## 2. 터미널 전송 설계 (6.1.2)

### 2.1 M0 결정의 재개정

M0 0.2.4 는 바이너리 프레임을 **1차 불채택**하되 "필요 시점에 capability 로 추가한다"는 경로를 함께 남겼다. 터미널이 그 시점이다. 와이어 버전은 그대로 두고, 데몬이 `features.terminalBinaryFrames` 를 광고하며 클라이언트가 그 플래그를 보고 기능을 노출한다(없으면 **숨긴다** — 폴백 경로 금지).

### 2.2 프레임 포맷

같은 WebSocket 위에 텍스트(JSON)와 바이너리를 혼재한다. 바이너리 프레임의 첫 두 바이트가 라우팅 정보다.

```
[opcode:1][slot:1][payload...]
```

| opcode | 방향 | 의미 |
|---|---|---|
| `0x01` | 데몬 → 클라이언트 | 터미널 출력 바이트 |
| `0x02` | 클라이언트 → 데몬 | 터미널 입력 바이트 |

- `slot` 은 **연결 단위**로 부여되는 1바이트 터미널 핸들(0~255). 터미널 ID(문자열)는 JSON RPC 로 주고받고, 슬롯 배정은 `terminal.attach` 응답이 알려준다. 매 프레임에 문자열 ID 를 싣지 않기 위한 장치다.
- 슬롯은 연결이 끊기면 무효다. 재연결 후에는 다시 attach 해서 새 슬롯을 받는다.
- 미지 opcode 프레임은 **조용히 버린다**(관대 파싱, NFR-5).

### 2.3 스키마 순수성과의 관계

프로토콜 패키지의 순수성 게이트(`.transform()/.catch()/.preprocess()` 금지)는 **JSON 와이어 스키마**에 대한 규칙이다. 바이너리 채널은 zod 검증 대상이 아니며, 대신 다음을 강제한다.

- 프레임 파서는 protocol 패키지에 **순수 함수**로 둔다(`encodeTerminalFrame` / `decodeTerminalFrame`). 데몬·렌더러가 같은 구현을 쓴다.
- 길이·슬롯 범위 검증 실패는 예외가 아니라 `undefined` 반환으로 다룬다(연결을 끊지 않는다).

### 2.4 RPC 표면

| 메서드 | 요청 | 응답 |
|---|---|---|
| `terminal.create` | `{ workspaceId, cols, rows, shell? }` | `{ terminal }` |
| `terminal.list` | `{ workspaceId? }` | `{ terminals }` |
| `terminal.attach` | `{ terminalId, cols, rows }` | `{ slot, scrollback }` |
| `terminal.detach` | `{ terminalId }` | `{}` |
| `terminal.resize` | `{ terminalId, cols, rows }` | `{}` |
| `terminal.kill` | `{ terminalId }` | `{}` |

이벤트: `terminal_changed`(생성·종료·제목 변경) — 레지스트리 이벤트와 같은 "다시 읽어라" 신호 형태.

### 2.5 스크롤백과 재접속

- 데몬이 터미널마다 **고정 크기 링 버퍼**(기본 256KiB)로 최근 출력을 보관한다. `attach` 응답에 그 스냅샷을 담아 보내고, 그 이후 출력은 바이너리 프레임으로 잇는다.
- 스냅샷과 이후 스트림 사이에 **중복·누락이 없도록**, attach 처리 중 도착한 출력은 스냅샷 뒤에 이어 붙인 다음 슬롯을 활성화한다(attach 는 터미널별로 직렬화).
- 링 버퍼가 넘치면 앞을 버린다. 클라이언트는 "이전 출력 일부가 잘렸다"를 표시한다.

### 2.6 크기(cols/rows) 소유권

- pty 크기는 **마지막으로 resize 를 보낸 attach 세션**이 정한다. 여러 클라이언트가 붙으면 마지막 것이 이긴다.
- detach 후 남은 attach 가 없으면 크기를 유지한다(프로세스가 갑자기 좁아지지 않게).

## 3. 파일·변경사항 (6.4·6.5 입력)

- `file.tree` / `file.read` 는 **워크스페이스 상대 경로만** 받는다. `..` 이 포함되거나 정규화 후 워크스페이스 밖을 가리키면 거절한다 — 데몬은 워크스페이스 경계를 넘는 읽기를 수행하지 않는다.
- `file.read` 는 크기 상한(기본 2MiB)과 바이너리 판정(널 바이트 검출)을 둔다. 초과·바이너리는 내용 대신 메타데이터만 돌려준다.
- diff 는 구독형이다: `diff.subscribe { workspaceId, scope }` → `diff_changed` 이벤트 → 클라이언트가 `diff.get` 으로 회수. 재연결 시 구독은 클라이언트가 다시 건다(데몬이 구독 상태를 영속하지 않는다).

## 3.5 자식 세션 트랙 (7.3.3)

부모-자식 관계는 **탭이 아니라 트랙**으로 보여 준다. 형제 세션(같은 워크스페이스의 독립 세션)은 탭·페인이고, 위임한 자식은 부모 화면 위의 한 줄이다 (FR-9.3).

자식을 탭으로 승격시키지 않는 이유는 **자리 다툼**이다. 위임한 작업 5개가 탭 5개가 되면 사용자가 하던 일이 밀려난다. 트랙은 "무엇이 돌고 있고 얼마를 썼는가"만 보여 주고, 눌렀을 때 비로소 탭이 열린다 — 자식도 1급 세션이라 직접 대화할 수 있어야 하기 때문이다(FR-9.3).

트랙에 싣는 것:

- 자식별 **상태 점 · 하네스 · 그 가지 전체의 토큰**. 자식 자신의 사용량이 아니라 자손까지 포함한 합을 쓴다 — 판단 기준은 "이 가지가 통째로 얼마를 썼나"다.
- **합계와 내 대화를 나눈 표시**(FR-9.3 이 사용량 합산을 필수로 요구한다). 부모의 대화가 싸도 위임이 비쌀 수 있고, 그 구분이 없으면 "왜 예산이 줄었나"를 판단할 수 없다.
- 자식이 자식일 때는 **부모로 돌아갈 길**. 자식 탭을 열면 그 세션이 왜 존재하는지가 화면에서 사라지므로, 되돌아갈 링크가 없으면 맥락을 잃는다.

값은 `session.usage` 를 그대로 쓴다. **렌더러가 합산을 다시 계산하지 않는다** — 데몬의 팬아웃 게이트가 세는 값과 갈라지면 사용자가 보는 "자식 2개"와 상한이 막는 기준이 달라진다(7.3.2 결정).

조회는 **열려 있는 세션 탭에 대해서만** 한다. 목록 전체를 훑으면 세션 수만큼 RPC 가 나가고, 화면에 없는 세션의 트랙은 아무도 보지 않는다. 갱신 시점은 탭 적재와 세션 목록 갱신 두 곳이다 — 후자를 빠뜨리면 트랙이 탭을 다시 열 때까지 낡는다.

자식도 부모도 없으면 **트랙 자체를 그리지 않는다**. 위임을 쓰지 않는 세션에 빈 줄을 남기지 않는다.

## 3.6 커맨드 팔레트 (7.4.2)

`Mod+K` 로 여는 단일 입력창. 소스 다섯: **명령 · 세션 · 워크스페이스 · 파일 · 대화 내용** (FR-9.4).

### 3.6.1 어려운 것은 검색이 아니라 한 줄에 세우기

다섯 소스는 출처도 지연 시간도 다른데 사용자는 목록 **하나**를 위아래로 훑는다. 그래서:

- **점수 계산은 렌더러 한 곳에만** 둔다(`palette/items.ts`). 소스별로 흩으면 파일만 다른 규칙으로 정렬된다. 데몬이 이미 걸러 온 것(파일 후보·타임라인 히트)도 여기서 다시 순위를 받는다 — **데몬은 "무엇이 후보인가"를, 렌더러는 "어떤 순서인가"를 정한다.**
- 판정은 **부분 문자열 우선, 부분 수열 차선**이다. `index` 로 `index.ts` 를 찾는 것이 `i…n…d…e…x` 로 흩어져 맞는 것보다 의도에 가깝다. 같은 방식 안에서는 매치가 이른 쪽이 앞.
- **대화 내용만 예외로 점수를 매기지 않는다.** 데몬이 이미 최근순으로 골라 온 결과이고, 잘린 스니펫에 라벨 점수를 다시 매기면 데몬의 순서를 근거 없이 뒤엎는다.
- 지금 쓸 수 없는 명령은 **아예 안 보인다**(활성 탭 없음 → "탭 닫기" 없음). 눌러도 아무 일이 없는 항목은 없는 것보다 나쁘다.

### 3.6.2 원격 응답의 경합

파일·대화 내용은 타이핑마다 RPC 가 나가고 순서 보장이 없다. 늦게 온 옛 응답이 새 결과를 덮으면 사용자는 화면에 없는 것을 누른다.

**질의 문자열이 아니라 요청 순번으로 막는다.** 같은 글자를 지웠다 다시 치면 질의는 같지만 앞 요청의 답이 뒤에 올 수 있다 — 세는 것은 "몇 번째 요청인가"다. 더해서, 화면에 세울 때도 원격 결과는 **그 질의의 답일 때만** 쓴다(`resultsFor`). 아니면 질의가 바뀌는 사이 옛 파일이 잠깐 섞여 보인다.

로컬 소스(명령·세션·워크스페이스)는 응답을 기다리지 않는다. 팔레트가 잠깐이라도 빈 화면이 되면 사용자는 그냥 닫는다.

### 3.6.3 `file.search` 를 신설한 이유

`file.list` 는 트리를 펼치는 **한 단계** 조회다. 팔레트는 "이름 일부만 아는 파일"을 찾아야 해서 전체 순회가 필요하다 — 그래서 별도 RPC 다. 워크스페이스 크기는 우리가 못 정하므로(사용자 저장소다) 훑는 파일 수에 상한을 둔다. 순회는 **너비 우선**이다: 상한에 걸려도 얕은 경로가 먼저 차면 사용자가 아는 파일이 남을 확률이 높다. 경계·무시 규칙(`.git`·`node_modules`, 심링크 미추적)은 §3 과 같다.

### 3.6.4 검색 결과가 내리는 자리

타임라인 항목이 **자기를 연 이벤트의 `seq`** 를 들고 있다. 7.4.1 이 검색 결과에 실어 준 앵커가 여기로 내린다.

목표는 **앵커 이하 중 가장 큰** 항목이다 — 어시스턴트 항목은 `turn_started` 에서 만들어지고 검색 세그먼트의 앵커는 첫 델타라 둘이 정확히 같지 않다. 찾아간 뒤에는 추적(자동 하단 스크롤)을 끈다: 켜 둔 채로 이동하면 다음 델타 한 번에 바닥으로 되돌아가 찾아온 자리가 사라진다.

## 4. 폐쇄망·보안 고려

- **셸 실행 경로가 하나 더 생긴다.** 터미널은 워크스페이스 `cwd` 에서 사용자 셸을 띄운다. 이것은 하네스가 이미 수행하는 것과 같은 권한 수준이며 새로운 권한 상승은 아니지만, 감사 관점에서 다음을 둔다.
  - 터미널 생성·종료를 데몬 로그에 남긴다(명령 내용은 남기지 않는다 — 입력 로깅은 하지 않는다).
  - 설정으로 터미널 기능 전체를 끌 수 있다(`terminal.enabled`, 기본 on). 조직 정책상 금지하는 경우를 위한 스위치다.
- 터미널은 게이트웨이 통제와 무관한 경로다(LLM 트래픽이 아니다). NFR-1 스모크의 판정 대상에서 터미널이 띄운 자식 프로세스는 제외하지 않는다 — 사용자가 띄운 명령이 외부로 나가면 그건 사용자의 행위다. 다만 스모크는 터미널을 쓰지 않는다.

## 5. 번들 영향

- 터미널 렌더링(xterm 계열)과 구문 강조 라이브러리가 새 의존으로 들어온다. 둘 다 **오프라인 성립**이 조건이다(런타임 CDN 페치 금지). 6.7.2 에서 3 OS 재조립 후 크기 영향을 측정하고, 필요하면 지연 로드로 초기 로딩을 보호한다.

## 6. 결정 (2026-08-30 승인)

- **E-1 확정**: **`node-pty` prebuilt**. 진짜 pty 여야 색·라인편집·TUI(vim·top)가 성립한다 — 파이프 기반은 "모았는가 보는 창"에 그친다. 대가는 네이티브 모듈이 Electron ABI 에 묶인다는 점이며, 다음을 조건으로 받는다.
  - prebuilt 가 우리 Electron ABI·3 OS 에 성립하는지를 **6.3 착수 전 스파이크로 먼저 확인**한다(6.3.0). 성립하지 않으면 그 시점에 파이프 축소안으로 되돌린다.
  - 번들 빌드는 사외에서 수행하므로 **사용자 PC 에 빌드 도구가 필요하지 않다**. `.node` 바이너리를 동봉하고 manifest 체크섬 대상에 포함한다.
  - 코드 서명(C-3) 범위에 네이티브 모듈이 추가된다 — M3 서명 절차 문서에 반영한다.
- **E-2 확정**: 스크롤백 링 버퍼 **256KiB/터미널**, 넘치면 앞을 버리고 클라이언트가 상단에 "이전 출력 일부 잘림"을 표시한다. 설정으로 조절하지 않는다(먼저 쓰고, 불만이 관측되면 그때 연다).
- **E-3 확정**: 기본 셸은 POSIX 에서 `$SHELL`(없으면 `/bin/sh`), Windows 에서 **PowerShell**. `terminal.shell` 설정으로 덮을 수 있다. Windows 의 Git Bash 는 pi 조건부 지원과 얽혀 있으므로 실기기(C-5) 확인 후 판단한다.
