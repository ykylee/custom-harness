### 수용 검증이 찾아낸 결함 2건 (선언 전 수정 완료)

완료 선언을 문서 작업으로 끝내지 않고 실제로 돌린 결과, 각 WP 의 단위 검증이 덮지 못한
**경로 사이의 결함**이 드러났다. 둘 다 고치고 회귀 테스트를 남겼다.

1. **데몬 종료가 주의 상태를 지웠다.** 세션을 닫을 때 `pending` 을 비운 뒤 주의 상태를 다시
   계산하면 "승인 대기"가 거짓으로 `false` 가 되어 영속된다. 종료는 **모든** 세션을 닫으므로
   재기동 때마다 통째로 지워졌다 — FR-9.1 이 없애려던 실패(클라이언트가 없는 동안 생긴
   신호가 사라진다)를 데몬이 스스로 만들고 있었다. 기존 7.1 테스트는 *새 매니저를 같은
   저장소 위에 세우는* 크래시 경로만 덮어 이 구간이 비어 있었다. → 런타임이 없으면 주의
   상태를 **얼린다**(사용자가 명시적으로 닫을 때만 내린다).
2. **`wait` 직후의 `result` 가 방금 기다린 턴을 못 봤다.** `waitForTurn` 은 `applyEvent`
   안에서 풀리는데 그 이벤트의 **파일 기록은 아직 쓰기 체인 위에** 있다. 위임의 정해진
   순서(`session_wait` → `session_result`)가 빈 결과를 읽을 수 있었다 — 실물 하네스는
   지연이 있어 가려졌다. → 두 조회가 체인을 먼저 비운다(`session.timeline` 재동기화도 동일).

### 잔여 (M7 범위 밖으로 넘김)

- 토큰 예산 상한은 **구현 (2026-09-03)**: `tools.maxSubagentTokens`(기본 0=비활성)가 자식·자손 합계로 `session_new`·`session_say`를 차단한다. 미보고 가지는 허용으로 보지 않는다.
- `autoApprove` 가 켜져 있으면 역방향 툴 승인도 자동 통과한다. 역방향 툴만 따로 두는 정책이 필요한지는 FR-1.5 후속.
- 제목 **수동 편집** 경로 없음 — 필요 시 `session.title.set` RPC 로 별도 항목.
- 파일 검색은 질의마다 워크스페이스를 다시 훑는다(캐시 없음). 큰 저장소에서 체감되면 워처 기반 인덱스로 승격.
- Windows 에서의 홈 격리 성립 여부는 **C-5 실기기** 항목(사내 협조).
