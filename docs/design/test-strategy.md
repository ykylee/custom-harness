- 문서 목적: 계층별 테스트 방식과 CI 게이트를 확정한다.
- 상태: approved (v1, 2026-08-25 사용자 승인)
- 최종 수정일: 2026-08-25
- 입력: [NFR](../requirements/nfr.md), [어댑터 설계서](./adapter-contract.md), [개발 표준](./dev-standards.md)

## 1. 계층별 테스트

| 계층 | 방식 | 도구 |
|---|---|---|
| protocol | 스키마 라운드트립 + 순수성 검사(transform 금지 lint 규칙) | vitest + 커스텀 lint |
| 어댑터 **계약 테스트** | 전 계약 메서드·이벤트를 mock 하네스와 실제 어댑터 양쪽에 동일 스위트로 실행. 미지 이벤트/필드 주입 → `other` 통과 검증 (NFR-5) | vitest 공유 스위트 |
| 어댑터 실통합 | 실제 하네스 바이너리 + **로컬 목 게이트웨이**(스파이크에서 검증한 방식)로 1턴 시나리오 — pi(JSONL RPC)·omp(v2 청킹 포함)·grok(ACP) | vitest + mock-gateway 픽스처 |
| 데몬 | 세션 매니저 상태 전이·interrupt 멱등·승인 pending 복원·PID 원장 회수 — mock 어댑터로 | vitest |
| 렌더러 | 컴포넌트 스냅샷 최소 + 이벤트 스트림 재생 기반 뷰 검증(mock 어댑터 타임라인 재생) | vitest + testing-library |
| E2E | Electron 앱 기동 → 온보딩 → mock 하네스 세션 1턴 → 승인 응답 → 재시작 재개 | Playwright(Electron) — M1 후반 도입 |

- **mock 이 2종**: mock 어댑터(프로세스 없음, 계약 기준점) + mock 게이트웨이(OpenAI 호환 HTTP, 스트리밍·에러·지연 주입 가능). 스파이크의 mock-server 를 픽스처로 승격.

## 2. NFR-1 네트워크 캡처 스모크 (CI 게이트의 핵심)

- 표준 시나리오: 설치(스크립트) → 온보딩(mock 게이트웨이 키) → 하네스별 1턴 → 종료.
- 캡처 방식: 테스트 러너가 **DNS/이그레스 프록시 강제 + 프로세스별 커넥션 로깅**(macOS/Linux: pf/iptables 대신 1차는 `HTTP(S)_PROXY 강제 + 프록시 화이트리스트` — 하네스가 프록시를 우회하는지 자체가 검증 대상이므로 **보조로 lsof 기반 커넥션 스냅샷 폴링** 병행). 완전한 패킷 캡처 CI 는 M2 에서 강화 (개정 포인트).
- 판정: 허용 목적지(127.0.0.1 목 게이트웨이) 외 커넥션 1건이라도 있으면 실패. pi 첫 실행 fd 다운로드(실측 발견)가 첫 검출 대상.

## 3. CI 게이트 (단계 도입)

| 게이트 | 도입 시점 | 필수/경고 |
|---|---|---|
| typecheck + lint + protocol 순수성 | M1 1.1.1 | 필수 |
| 계약 테스트 (mock) | M1 1.3.4 | 필수 |
| NFR-1 스모크 (pi) | M1 1.7.2 | 필수 |
| 어댑터 실통합 (3종) + NFR-1 확장 | M2 2.7.1 | 필수 |
| NFR-3 바인드·토큰 검사 | M2 | 필수 |
| E2E (Electron) | M2 후반 | 경고 → M3 필수 |
| COMPAT 만료 스캔 | M1 부터 | 경고 (만료분은 필수) |
| 설치 원자성(중단 주입) | M3 3.1.3 | 필수 |

- CI 환경: 사외 개발 환경 (폐쇄망 모사 = 목 게이트웨이 + 이그레스 차단). 실 게이트웨이 검증은 파일럿(M3)에서.
