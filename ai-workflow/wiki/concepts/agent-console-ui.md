# 에이전트 콘솔 UI (Agent Console UI)

에이전트 UI는 대화의 외형보다 **위임·감독·회수**가 쉬운 작업 콘솔이어야 한다. 사용자는 현재 세션이 무엇을 어떤 경계 안에서 실행하는지 알고, 위험 행동을 결정하고, 언제든 중단·수정·재개할 수 있어야 한다.

## 세션 계약은 항상 보인다

대화 상단은 하네스·모델·작업 경로·승인 정책을 고정해 보인다. 이 값은 장식이 아니라 사용자가 에이전트에게 위임한 실행 조건이다. 타임라인을 오래 읽지 않아도 어느 환경에서 어떤 규칙으로 동작하는지 판단할 수 있어야 한다.

## 상태는 한 정책, 한 표현이다

`initializing`·`idle`·`running`·`closed`·`error`와 미응답 승인은 렌더러의 공통 표시 정본에서 한국어 레이블과 의미 색을 얻는다. 승인은 실행 상태보다 우선한다. 단, 무엇을 주의해야 하는지는 [[attention-state]]의 데몬 정본을 대체하지 않는다.

색만으로 상태를 전달하지 않는다. 상태 칩은 레이블을, 사이드바 점은 접근 가능한 이름을 함께 가진다.

## 승인 카드는 행동의 영향과 선택을 설명한다

권한 요청은 종류가 보장하는 범위까지만 설명한다: 셸은 명령 실행, 파일 쓰기는 파일 변경, fetch는 외부 연결이다. 임의의 상세 페이로드에서 대상·위험도를 추측하지 않는다. 요청 출처와 세션 한정 적용 범위를 보인 뒤, 한 번 허용·거부와 지속 정책을 시각적으로 구분한다.

응답 직후에는 중복 제출을 막고, 해결된 뒤에는 사용자가 선택한 결과를 남긴다. 자동 승인은 이 세션에서만 유효한 강한 정책이므로 세션 계약에 지속 표시한다.

## 검증 기준

- 실행 중·승인 대기·오류의 상태를 텍스트만으로 구별할 수 있다.
- 승인 버튼은 키보드로 도달 가능하고 첫 응답 이후 중복 제출되지 않는다.
- 폭이 좁은 분할 페인에서도 상태와 중단 조작은 숨겨지지 않는다.

이 원칙은 [[workbench-canvas]]의 탭·패널 모델 위에서 적용한다. 에이전트 루프와 정책 집행은 하네스·데몬이 소유하며 UI는 그 사실과 사용자 통제면을 드러낸다.
