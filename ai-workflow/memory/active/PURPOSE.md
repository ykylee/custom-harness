# PURPOSE

- 문서 목적: custom-harness 프로젝트의 방향성(목표·핵심 질문·범위·가설)을 정의한다.
- 상태: draft
- 최종 수정일: 2026-08-24

## 1. Goals

- **G1**: LLM 에이전트를 직접 실행·제어할 수 있는 커스텀 하네스를 만든다 — 모델 호출, 툴 루프, 프롬프트 구성을 우리가 원하는 방식으로 조립할 수 있는 실행 기반.
- **G2**: 기성 프레임워크에 의존하지 않고 에이전트 루프의 각 단계(컨텍스트 구성 → 모델 호출 → 툴 실행 → 결과 반영)를 투명하게 관찰·수정할 수 있게 한다.
- **G3**: 실험을 반복하기 쉬운 구조를 유지한다 — 프롬프트·툴셋·모델 교체가 코드 전반의 수정 없이 가능해야 한다.

## 2. Key Questions

- **Q1**: 에이전트 루프의 최소 구성 요소는 무엇이며, 어디까지를 하네스가 책임지고 어디부터를 사용자 코드에 맡길 것인가?
- **Q2**: 툴 실행을 어떻게 안전하게 격리할 것인가 (샌드박스, 권한, 실패 처리)?
- **Q3**: 어떤 언어/스택이 이 하네스에 적합한가? (현재 미정 — 초기 프로토타입 후 결정)
- **Q4**: 세션 상태(대화 이력, 컨텍스트 관리)를 어떻게 저장·복원할 것인가?

## 3. Research Scope

### 포함 영역

- 에이전트 실행 루프 (모델 호출, 툴 디스패치, 결과 반영)
- 프롬프트/컨텍스트 구성 및 관리
- 툴 정의·실행·격리 방식
- 세션 상태 저장과 복원
- 기술 스택 선정을 위한 프로토타이핑

### 제외 영역

- 범용 프레임워크화 / 외부 배포용 라이브러리 패키징 (초기 단계에서는 자체 사용 목적)
- 웹 UI / 프런트엔드 (하네스 코어가 우선)
- 멀티테넌트 운영·과금 등 서비스화 관심사

## 4. Evolving Thesis

기성 에이전트 프레임워크는 추상화가 두꺼워 루프 내부를 관찰·개조하기 어렵다. 얇고 투명한 자체 하네스를 만들면 프롬프트·툴·컨텍스트 실험의 반복 속도가 빨라지고, 에이전트 동작에 대한 이해도 깊어질 것이다. 스택은 프로토타입 검증 후 확정한다.
