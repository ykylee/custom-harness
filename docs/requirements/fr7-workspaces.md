# FR-7 상세 — 프로젝트 · 워크스페이스 모델

## FR-7.1 프로젝트 레지스트리 (M, M5)

- 프로젝트 = 사용자가 선택한 **정확한 루트 디렉토리** 1개. 식별자는 불투명 ID(`prj_<hex>`)로 발급하고, 경로는 lexical 정규화(`path.resolve`)만 한다 — `realpath` 로 심링크를 동일시하지 않는다.
- 같은 루트에 대한 재요청은 멱등(기존 프로젝트 반환). 아카이브된 프로젝트는 부활하지 않는다.
- git 저장소면 remote 를 메타데이터로 기록한다. remote 부재도 정상 상태다(폐쇄망 로컬 저장소 고려).
- **식별자와 가변 메타데이터를 분리한다**: 정합화 과정은 git 파생 메타데이터(kind·현재 브랜치)만 갱신하고, `projectId`·루트 경로·표시 이름은 변경하지 않는다.

## FR-7.2 워크스페이스 레지스트리 (M, M5)

- 워크스페이스 = 프로젝트의 체크아웃 1개 = **에이전트가 일하는 단위**. 기본 워크스페이스는 프로젝트 루트 그 자체.
- 레코드는 `cwd`(실행 디렉토리)와 `checkoutRoot`(백킹 체크아웃 루트)를 **분리 보관**한다. 모노레포의 하위 패키지를 정확히 가리키기 위해 둘은 다를 수 있다.
- 상태: `active` / `archived`(소프트 삭제). 아카이브는 `cwd` 에서 teardown 을 수행한 뒤, 그 체크아웃을 참조하는 마지막 세션이 사라진 후에만 백킹 디렉토리를 제거한다.
- 라벨(문자열 key-value)을 붙일 수 있다. 라벨 카탈로그는 호스트 로컬 공용이며, 카탈로그와 할당의 동시 변경은 복구 가능한 단일 커밋으로 처리한다.
- 표시 이름은 사용자가 정하지 않으면 브랜치/디렉토리에서 유도한다(FR-9.5 자동 생성과 연계, 기본 규칙은 LLM 비사용).

## FR-7.3 세션의 워크스페이스 귀속 (M, M5)

- 모든 세션은 생성 시 `workspaceId` 를 부여받는다. **런타임은 cwd 로 소유권을 추론하지 않는다** — 같은 cwd 를 쓰는 형제 워크스페이스가 존재할 수 있다.
- 기존 세션 레코드(`workspaceId` 부재)는 1회 백필로 매핑한다. 백필이 cwd→id 매핑이 존재하는 유일한 지점이다.
- 세션 목록·상태 집계·사이드바 그룹핑은 전부 `workspaceId` 기준이다.

## FR-7.4 git worktree 격리 워크스페이스 (S, M5)

- 워크스페이스를 git worktree 로 생성할 수 있다: ① 새 브랜치 분기 ② 기존 브랜치 체크아웃. (PR 체크아웃은 사내 forge 확인 후 — FR-8.5 참조)
- 브랜치 이름 미지정 시 자동 생성한다(충돌 회피 포함).
- 백킹 worktree 가 외부에서 삭제된 경우, 메인 저장소 루트로부터 재생성하고 `checkoutRoot`→`cwd` 상대경로를 복원한다.
- worktree 미사용 모드(디렉토리 직접 선택)도 1급으로 지원한다 — git 아닌 프로젝트와 사내 정책상 worktree 를 못 쓰는 경우를 위해.

## FR-7.5 프로젝트 설정 파일 (S, M5)

- 저장소 루트의 프로젝트 설정 파일(가칭 `harness.json`)로 워크스페이스 수명주기를 선언한다.
  - `workspace.setup` — 워크스페이스 생성 직후 1회 실행. 다중 명령은 순차 실행.
  - `workspace.teardown` — 아카이브 직전 실행.
  - `scripts.<name>.command` — 워크스페이스 안에서 실행할 이름 붙은 명령.
- 설정 파일은 **베이스 브랜치의 커밋된 버전**에서 읽는다 (다른 브랜치의 미커밋 변경이 실행 경로에 새 나가지 않도록).
- setup/teardown 은 워크스페이스를 `cwd` 로 실행하며, 원본 체크아웃 경로를 환경 변수로 제공한다(미추적 설정 파일 복사용).
- **모든 실행은 사용자 확인을 거친다** — 저장소 파일이 곧 실행 명령이므로, 자동 실행은 프로젝트별 명시적 신뢰 표시 후에만 허용한다(NFR 보안 경계).

## FR-7.6 정보구조 재편 (M, M5)

- 사이드바는 **프로젝트 → 워크스페이스 → 세션** 3계층으로 재편한다. 기존 상태 버킷(대기/실행/주의)은 워크스페이스 하위 또는 횡단 필터로 유지한다.
- 워크스페이스 생성·아카이브·라벨 편집 UI 를 제공한다.

## FR-7.7 범위 제한

- 호스트(데몬) 다중화·프로젝트의 호스트 횡단 동일시는 범위 밖(단일 데몬 전제). 다만 프로젝트 레코드에 호스트 횡단 그룹핑 키를 넣을 자리는 optional 로 남긴다.
